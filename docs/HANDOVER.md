# 次の部員への引き継ぎ・運用の記録

この文書は、サイト担当が交代するときに「何が動いていて、誰が何を確認するか」を共有するためのものです。専門用語の設定手順は[Cloudflareバックエンド設定方針](CLOUDFLARE_SETUP.md)、サイトの全体像は[サイト構成と責任範囲](ARCHITECTURE.md)を参照してください。

## まず知っておくこと

- **旧サイト**：過去のCDに印刷済みの歌詞URLを維持するため、`endo1192/gu-sakkyoku-album`と旧Cloudflare Pagesを残します。新しいサイトを公開しても、旧URLを一律に転送・削除しません。旧環境は作曲部の新アカウントとは管理権限が別なので、将来の維持方法は旧管理者とも相談が必要です。
- **新サイト**：`gu-sakkyoku/gu-sakkyoku.github.io`の内容をGitHub Pagesで公開します。カードの共通入口は`/download/`です。印刷したQRの行き先は後から変えられないため、公開URLを実機で確認してから頒布します。
- **音源配信**：カードのコードはCloudflare Workerが照合し、ZIPは非公開R2から配信します。GitHubのソースコードにはコード・ZIP・決済情報を置きません。
- **現在の状態（2026-09-26）**：2024・2025の配布用ZIPを非公開R2へ登録し、両方とも元ファイルとのSHA-256一致を確認しました。2026は準備中です。作曲部アカウントのWorkerと本番Turnstileは設定済みで、リポジトリはPublic、GitHub Pagesの公開元はGitHub Actionsです。**購入者の画面からの正規ダウンロード・スマホでのQR確認は別途必要**です。**支払い責任者は部内で暫定決定済み**ですが、氏名・支払い方法はここには記録しません。この状態は本番設定のたびに更新してください。

## 役割と引き継ぎ先

| 役割 | 引き継ぐ仕事 |
| --- | --- |
| 部の代表・共同管理者 | 方針と費用の承認、権限の付与・見直し、変更のレビュー |
| 会計・支払い担当 | 契約内容、請求書、支払い方法、請求メール、料金通知の確認 |
| サイト担当 | 歌詞・アルバム情報の更新、ZIPの登録、Workerと公開ページの動作確認 |
| 購入者対応の窓口 | QRやコードが使えないときの連絡の受け付けと担当への連携 |

これは役割の例です。担当者の名前・連絡先・カード情報をこのリポジトリへ書かず、部がアクセスを管理する非公開の場所に保存してください。少なくとも「誰に連絡すればよいか」を部内で共有し、担当交代時に更新します。

Cloudflareでは[請求に関する権限](https://developers.cloudflare.com/billing/understand/billing-permissions/)が役割によって異なります。`Billing`は支払い方法を変更できますが契約を変更できず、`Administrator`は契約を変更できますが支払い方法を変更できません。両方とメンバー管理が必要な人には`Super Administrator`が必要です。必要な権限だけを付け、部内で誰が有料契約を承認するかを別途決めてください。権限があることと、部費を使ってよいという承認は別です。

## 卒業・交代前のチェックリスト

1. **状態を確かめる。** 新サイトの公開URL、旧URL、GitHub Pagesの公開状態、Worker・R2・Turnstileの有無、2024以降の公開年度を後任と確認します。この文書の「現在の状態」も更新します。
2. **後任を先に招待する。** GitHub Organizationと作曲部Cloudflare Accountに、後任本人のアカウントを追加します。個人のログイン情報や二段階認証コードを共有しません。Cloudflareのメンバー変更は[公式の手順](https://developers.cloudflare.com/fundamentals/manage-members/manage/)に従います。
3. **料金の引き継ぎを確認する。** 会計・支払い担当がR2の契約状態、請求履歴、支払い方法、請求メール、利用量と料金通知の送付先を確認します。新担当が必要な請求画面を開けるかも確かめます。カード番号や請求書の個人情報はGitHubや公開チャットへ載せません。
4. **実際に操作する。** 後任が新旧の歌詞URLと共通QRを開き、公開済みの各年度について正しいコードでダウンロードできるか、間違ったコードでは取得できないかを確認します。2026など準備中の年度はダウンロードできないことも確認します。実際のコードをIssueやPull Requestへ貼りません。
5. **元データと秘密情報の所在を伝える。** ジャケット・歌詞・元ZIP・カード原稿の保管場所、CloudflareのSecretを再設定する方法、復旧連絡先を、部内の非公開の引き継ぎ資料で共有します。秘密の値そのものをこの文書に書く必要はありません。
6. **退任者の権限を整理する。** 後任が使えることと請求先を確認してから、部内の合意に沿って旧担当の権限や不要なAPI Tokenを削除・更新します。アクセスできる人が変わる場合は、ダウンロードコードなどの更新が必要かも判断します。先に唯一の管理者を外さないでください。
7. **引き継ぎ完了を記録する。** 実施日、担当した役割、未完了の作業、次回確認日を部内の非公開記録に残します。公開リポジトリには個人情報を載せず、この文書の状態だけを更新します。

## 運用上の問題点・限界

- **旧URLを自分たちだけで維持できるとは限らない。** 旧Cloudflare Pagesと旧リポジトリは別管理です。過去の購入者に影響する変更は旧管理者と調整し、変更前後に印刷済みURLを試してください。
- **無料枠は「請求が絶対にない」の意味ではない。** 2024・2025のZIPだけで合計約3GBあります。新年度のZIPが増えるとR2の保存量も増えます。[R2の料金](https://developers.cloudflare.com/r2/pricing/)と実際の利用量を定期的に確認してください。[Budget Alert](https://developers.cloudflare.com/billing/manage/budget-alerts/)は通知であり、利用を止める仕組みではありません。
- **年度共通コードは他人へ渡せる。** これは購入者を一人ずつ識別する仕組みではありません。コードが流出した場合の対応をあらかじめ決めてください。ただし、急なコード変更は正規の購入者も使えなくします。
- **担当者一人だけに依存すると止まる。** GitHub・Cloudflare・支払い・元ZIPの所在が一人にしか分からない状態を避けます。復旧方法は部内の非公開資料に記録し、複数人で確認します。
- **公開後に印刷物は修正できない。** QRのURLを変える場合は、古いカードをどう案内し続けるか決めてから実施します。新ドメインを追加しても`/download/`入口の継続を優先します。
- **音源の公開権限も確認が要る。** 収録曲・ジャケット・歌詞について、オンラインでの再配布が許可されているかを各年度の公開前に部内で確認します。

## 次の部員に議論してほしいこと

以下は**未決事項であり、この文書が答えを決めるものではありません**。部内で決めたら、個人情報や秘密を載せない範囲で決定と理由を記録してください。

| テーマ | 決めること・考える理由 |
| --- | --- |
| 費用と承認 | R2は有効化済み。今後の有料化・無料枠超過分を誰が承認するか。請求の負担・精算方法、予算、利用量の確認頻度、通知を見た後の対応はどうするか。支払い責任者の交代時に何を引き継ぐか。 |
| 権限と復旧 | GitHubとCloudflareの管理者を何人にするか。二段階認証・アカウント喪失・卒業にどう備えるか。 |
| 過去の購入者 | 旧歌詞URLを誰といつまで維持するか。旧サイトが使えなくなったときの連絡・移転方法をどうするか。 |
| 2024・2025のカード | 過去の購入者にも新しいダウンロードコードを提供するか。提供する場合、誰がどの方法で案内するか。 |
| コードの共有・流出 | 年度共通コードのままでよいか。流出時に、正規購入者を困らせずどう対応するか。 |
| 音源の保管と公開期間 | 年度ごとのZIPをいつまで提供するか。R2の無料枠が近づいた場合、削除ではなくどう告知・保管・予算化するか。 |
| 新しいコンテンツ | 2026以降の歌詞・ジャケット・音源を誰が承認して公開するか。試聴・ストリーミングを将来追加する必要があるか。 |
| URLと印刷物 | 今後も`gu-sakkyoku.github.io`を正式URLにするか、独自ドメインを使うか。変更するなら既存カードのQRをどう生かすか。 |
| 購入者サポート | QRが読めない・ZIPが開けない・コードが通らないとき、どこへ問い合わせてもらい、誰が対応するか。 |

## 決定を記録するときの書き方

部内で話し合ったら、議事録など**部内だけが見られる場所**に「決定日／参加した役割／決めた内容／理由／次の確認日／未解決事項」を残してください。この公開予定のリポジトリには、運用に必要な**決定済みの方針だけ**を個人情報なしで反映します。契約や料金について未確認のことは「未確認」のまま残し、推測で「無料」「設定済み」と書き換えないでください。
