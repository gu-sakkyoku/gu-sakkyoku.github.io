# ヘッダーとページ先頭の余白

## 何を直したか

Issue #6では、WQHDなどの大きい画面でロゴとヘッダーが大きくなり、ページのタイトルを隠す問題がありました。以前はロゴを画面幅の割合で表示し、歌詞ページの先頭に改行（`br`）を7個入れてヘッダーを避けていました。画面によってロゴの高さだけが変わるため、改行の数では安定しません。

今回は見た目の全面変更ではなく、次のように寸法の決め方を統一しています。

- ロゴはスマートフォンで48px、PCで64px（標準文字サイズの場合）。大きい画面でも際限なく拡大しません。
- ヘッダーはスマートフォンで80px、PCで96px。中のロゴ・サイト名・メニューは最大1280pxの範囲に収めます。
- 全ページで既存の`ClientWrapper`を使い、本文の先頭位置を同じCSSで決めます。名前は既存コードとの連続性のため残していますが、ブラウザーで高さを測る処理はもうありません。
- ロゴ・本文の余白はJavaScriptの読み込み前から決まります。
- トップとHoroscopeの重ねたジャケットは`AlbumJackets`にまとめ、最大1200pxの範囲に収めます。既存の画像・斜めの配置・通常時の揺れる演出は維持します。

歌詞本文の中にある改行は、歌詞の意味や区切りを保つために残しています。削除したのは**ヘッダーを避けるためのページ先頭の改行**です。

## 後から調整するとき

1. 高さと本文の余白は`src/app/globals.css`の`--site-header-height`・`--site-page-gap`で調整します。ヘッダーだけの高さを別の場所に書かないでください。
2. ロゴの寸法・メニューの見た目は`src/component/header.tsx`で調整します。元の割合指定へ戻さないでください。
3. PCとスマートフォンの切り替え幅は64rem（標準設定で1024px）です。変更する場合は`globals.css`、`header.tsx`のCSSと`matchMedia`、画像の`sizes`も揃えてください。
4. 新しいページは`ClientWrapper`で囲みます。ページの先頭に余白用の`br`や、ヘッダーを避ける別の`padding-top`を足す必要はありません。
5. メニューのリンクは`header.tsx`の`navigation`に一度だけ書きます。スマートフォン・PCの両方に反映されます。

## 確認すること

- スマートフォン（375px）、横向き、タブレット、切り替え境界（1023px・1024px）、WQHD（2560px）、4K（3840px）でタイトルが隠れないこと。
- トップ・ダウンロード・アルバム・各歌詞ページで横スクロールがないこと。
- Tabキーでロゴとメニューへ移動でき、選択位置が青い枠で見えること。閉じたメニューのリンクへ移動しないこと。
- Enterで開き、Escapeで閉じるとメニューボタンへ戻ること。PC幅へ広げた後も古い開閉状態が残らないこと。
- 明るい表示・暗い表示で文字を読めること。
- OSの「動きを減らす」設定ではメニューの切り替えとジャケットの揺れを止め、トップの待機演出を表示しないこと。
- `npm run check`が成功すること。

メニューはEscapeで閉じてボタンへ戻れます。Tabで本文へ進んだ場合も自動で閉じ、本文の操作位置を隠しません。

この変更で歌詞URL、アルバム情報、ダウンロードの認証、Cloudflare Worker / R2の設定は変更しません。2026年の新作告知と検索用のサイト名・アイコンも維持します。
